## A. Design tenets (SPEC §1)

| ID | Tenet | Verdict | Rationale under Hermes ground truth |
| --- | --- | --- | --- |
| T1 | Advisor, not gate | **STRENGTHENS** | The frame makes T1 *differentiated* rather than merely virtuous: the host already owns a gate (skills_guard `INSTALL_POLICY`) and ships a blocking-capable hook (`pre_tool_call`). X-Ray choosing observer-only hooks is now a visible, contrastive choice — and verifiable: doctor check #5 becomes "assert xray holds zero `pre_tool_call` registrations" against a concrete `VALID_HOOKS` set. A second gate would be redundant; a second opinion with depth is scarce. The tenet's exception clause ("exit codes gate only with `--fail-on`") survives unchanged but narrows to CLI surfaces (see §18 rows). |
| T2 | Deterministic core | **STANDS** | Language- and host-neutral. In-process timing variance is already quarantined in the `_meta` sidecar; Python dict-order hazards are neutralized by the specced `sort_keys=True` canonicalization. New pressure point named and handled: any future `ctx.llm` output must stay outside the canonical envelope exactly as the choir contract already stipulates (`llm_touched=true` excluded from determinism guarantees). |
| T3 | Explainable arithmetic | **STANDS** | Unaffected by host. One gain: `--explain-rules` also renders through `/xray explain-rules` into chat, where the agent itself can quote the weight math back at the user — mechanical explanation gets a second audience. |
| T4 | Local-first privacy | **STANDS** (enforcement restated) | Guarantee intact for the default path; enforcement wording must be re-derived for in-process Python: G1's socket-deny CI becomes pytest-socket around the package plus an import-contract test ("xray_plugin imports no network modules"); G3's "no networking symbols linked" (a compiled-language notion) becomes "no network imports in the default dependency closure." The serious new threat is internal temptation, not external leakage — see Q2: `ctx.llm` puts a one-call LLM lane inside arm's reach, so T4 needs its "no model code in the truth path" phrasing repeated as a review gate, not just a doc claim. |
| T5 | Obfuscation is data, not execution | **STRENGTHENS** | Stakes rose, rule unchanged. Pre-reframe, executing target content wrecked a scan; post-reframe it would run inside the user's live agent process — credential-bearing, tool-wielding, sometimes gateway-connected. Decode-as-data purity and pure-function fuzz-tested decoders are now load-bearing for host safety, not just scanner hygiene. Direct corollary logged at D-PROC/D-CRASH: native parser code paths deserve equal paranoia. |
| T6 | Findings cite evidence | **STANDS** | Unaffected by host. Mild synergy: evidence spans render as plain file:line text in slash output where the agent (or user) can immediately `read` the cited location in-session — citation quality becomes interactively checkable. |

## B. Architecture decisions (SPEC §6 D-table)

| ID | Decision | Verdict | Rationale under Hermes ground truth |
| --- | --- | --- | --- |
| D-LANG | Python 3.11+, rev. 2 | **STANDS** | The decision *is* the audited frame, and inspection confirms it was correctly derived: built-in plugins are ordinary Python packages loaded in-process; the host runs a single venv; `register(ctx)` is the universal seam. No residual Rust argument survives — triggers are verified best-effort observers (`try/except` wrappers), so startup budget is irrelevant. Keep the superseded analysis retired unless a v1.x standalone CLI ships. |
| D-PROC | In-process engines behind `Engine` protocol | **STANDS** (new caveat recorded) | Choice still right for pure-Python engines; bundles are small and IPC buys nothing. But the containment claim must be scoped honestly: host isolation covers **Python exceptions only**. Vendored tree-sitter grammars are native code parsing adversarial bytes *inside the agent's process* — exception handlers cannot catch a segfault. Required amendments: (a) fuzz corpus explicitly covers grammar inputs (already implied, make it normative); (b) doctor gains a crash-loop note if the parse subsystem repeatedly hard-kills; (c) document optional subprocess parse-isolation as the v1.0 escape hatch if field crashes appear. Exception isolation ≠ memory isolation — say so in SPEC §4. |
| D-CRASH | Engine failure ⇒ synthetic INFO finding; exit 2 total-only | **STANDS** | Matches verified host behavior (hook failures are caught, logged, never propagate). Amendment shared with D-PROC: the contract covers exceptions; native crashes are handled by process-level reality, not this mechanism. Exit-2 semantics confirmed CLI-only (PLAN already says so; §18 row). |
| D-PARSE | Tree-sitter sh/py/js grammars ship in v0.9 | **WEAKENS** (delivery story contradicts distribution story) | The rationale ("~2 MB in the binary") is Rust-era and quietly broken: there is no binary. Options per ground truth: declare `tree-sitter-*` as manifest `python_dependencies` — but the host **never auto-installs them**, only warns, so out-of-the-box behavior silently degrades to line-scanners for most installs; or vendor platform `.so`s into a git-installed repo — which re-commits the exact sin D-LANG rev. 2 rejected ("git-based plugin installs cannot carry platform binaries cleanly"). Surviving form: keep AST engines in v0.9 **iff** the plan pins one lane — declared deps + doctor check ("AST engines active or degraded") + the already-specced graceful line-scanner fallback as first-class, golden-tested output, not a shadow mode; else demote E4/E5 AST to v1.0 and ship line-scanners honestly. | D-STREETLAB | street/lab profiles, annotated lab discounts | **STANDS** | Nothing in the host touches severity philosophy. If anything, hub trust levels tempt a *third* implicit profile ("trusted ⇒ softer") — rejected at the scoring row below; the explicit two-profile schema is the bulwark. Annotation discipline `[lab:declared-offensive]` unchanged. |
| D-RULEOWN | Core pack pinned, manual updates, SHA-pinned community packs | **STANDS** (wording restated) | "Compiled-in binary" language is obsolete — PLAN already moved packs to YAML in-repo, and that is *better* than the original rationale: engine + pack versions now travel together through git tags, so a plugin version pins its detection logic by construction; `hermes plugins update` is the manual update channel D-RULEOWN wanted.
